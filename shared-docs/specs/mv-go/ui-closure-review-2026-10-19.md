## Priority findings and disposition

1. P1 unsupported company New/Edit links: replaced by the supported company-profile action with permission gating.
2. P1 failed profile query becoming a blank editable form: RecordState/retry prevents accidental creation.
3. P1 mouse-only task/incident detail rows: named native detail buttons, including read-only users.
4. P1 360px rate-card navigation clipping/overlap: wrapping tabs with bounded trigger height; final keyboard End reaches the last tab.
5. P1 narrow chat composer: layout follows actual container width; mobile drawers close after navigation.
6. P1 inaccessible custom image gallery: shared named modal, keyboard zoom/pan, pointer handling and nested Escape isolation.
7. P1 unnamed date/time picker and nested clear action: separate real clear button, localized hour/minute searchable controls.
8. P1 visible form labels unassociated with controls: inherited Field naming plus the complete concrete source-audit follow-up batch, including HR/holiday rows and file fields.
9. P1 mobile Expense audit tabs escaped the page width: final batch wraps all four44px tabs; measured root scrollWidth equals360px.

User decisions implemented: mobile task rows summarize task, driver and status with details; leaving an unsaved permission matrix asks for confirmation. Drafts are not persisted. The guard covers links, quick jump, tenant switch, sign-out, unload and history traversal, with regression tests for cancel/accept/save/unmount.

Persona walkthroughs: dispatch staff can scan a task and open its existing detail; a phone-based partner/customer has the same summary and read-only detail path; accounting/HR users can identify every repaired field; platform admins retain edits when navigation is cancelled. Source-only conclusions are identified in the independent reports; native touchscreen hardware was not certified.

Cognitive load: the 12–13-column task table is replaced on phones by the summary; desktop retains the detailed table and action menu. Chat uses drawers where a three-column layout would squeeze the composer. Role edits show a pending count and a leave guard. These reduce forced horizontal search and accidental context loss.
