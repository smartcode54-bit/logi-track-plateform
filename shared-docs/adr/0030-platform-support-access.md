# ADR 0030 — Read-only platform support sessions with tenant-controlled disclosure

- **Status:** Accepted (owner approval 2026-10-16)
- **Deciders:** Samart Kas (product owner; requirements decided 2026-10-15, D1–D5 final on 2026-10-16); technical implementation awaits owner approval
- **Area:** logitrack-api auth/authz/IAM, PostgreSQL/RLS, tenant response domains, storage/jobs/SSE, logitrack-web BFF and navigation

## Context

The owner requires a `platform_admin` to enter any own-fleet or carrier tenant without membership, see its full staff menu, and remain read-only in tenant data. Quarantine is excluded. A real tenant administrator controls a persistent ON/OFF support-access setting: OFF masks personal information, files and money as `****` while retaining structure, statuses, counts, dates and plates; ON reveals real data without enabling writes. Company selection belongs in a searchable header modal. Entry, exit and consent changes must be visible in the tenant's Security Center. These requirements, refined by final owner decisions D1–D5 recorded in spec §3, are fixed. Phase 1 makes Dashboard and the entire Fleet & partners category available; other tenant destinations keep their menus and show a localized unavailable state until their domain slice ships. This ADR proposes the technical realization, not an already implemented feature.

The current implementation has two different mechanisms, neither meeting that contract:

- `POST /v1/auth/tenant` requires a usable membership, changes the session's active tenant and the user's remembered tenant, and audits arrival only (`logitrack-api/internal/auth/me.go:355`). Refresh chooses a membership again, and `/me` finds the active tenant only in its membership list (`logitrack-api/internal/auth/refresh.go:125`, `logitrack-api/internal/auth/me.go:74`).
- `X-Act-On-Tenant:<uuid>` lets platform_admin act as tenant_admin, including writes; `*` permits read-only all-tenant access. Both are audited per request (`logitrack-api/internal/iam/authorize.go:35`). Capability resolution unions platform defaults, which include user/security mutations, with tenant defaults (`logitrack-api/internal/authz/resolve.go:123`, `logitrack-api/internal/authz/roles.go:70`).

The security review also confirmed headerless platform IAM takeover paths: `writeReach` and `isTenantAdminOf` allow platform grants to any tenant, and temporary-password issuance returns a credential (`logitrack-api/internal/iam/admin.go:171,187`, `logitrack-api/internal/iam/users.go:886`). Matrix routes vary by query `layer/tenantId`; API-key creation varies by body `tenantId` (`internal/iam/admin_http.go:784,806`, `internal/iam/apikeys.go:80,336`, under `logitrack-api/`). Platform tenant/subcontractor reads return contacts, ID-card data and signed documents, while stewardship widens reach (`logitrack-api/internal/iam/tenants.go:136,187`, `logitrack-api/internal/iam/subcontractors.go:248`, `logitrack-api/internal/authz/resolve.go:111`). A method/path allowlist and a direct consent membership check alone cannot close these paths. Spec §3 records the complete code-verified review: findings 1–7 and 9–23 are applied; **finding 8 is rejected because its idle/extra absolute cap conflicts with final D4**. “Applied” describes this design, not a code implementation.

RLS restricts rows, not fields. The principal can request PostgreSQL READ ONLY transactions, but IAM uses separately authorized system transactions and storage/jobs contain platform-wide shortcuts (`logitrack-api/internal/platform/db/principal.go:44`, `logitrack-api/internal/iam/admin.go:117`, `logitrack-api/internal/storage/service.go:508`, `logitrack-api/internal/jobs/http.go:38`). A virtual role without changes to these paths would be insufficient.

The existing JSON writer accepts arbitrary data and metadata. Monetary DTO fields include non-nullable numbers; security events and payroll line metadata contain raw JSON. File endpoints return redirects to signed URLs, evidence galleries accept anonymous bearer links with no expiry by default, and SSE forwards event bodies (`logitrack-api/internal/platform/httpx/response.go:23`, `logitrack-api/internal/hr/payroll.go:22`, `logitrack-api/internal/security/feed.go:59`, `logitrack-api/internal/storage/http.go:114`, `logitrack-api/internal/storage/evidence.go:19`, `logitrack-api/internal/sse/sse.go:725`). Hiding React fields cannot close these disclosure paths.

The web already selects the staff navigation profile for platform roles before checking carrier membership. Its route map, however, uses management keys for several read pages. React Query clears state when user/tenant identity changes; most query keys do not themselves include tenant, and same-tenant claim refresh retains existing data while refetching. The edge capability cache lasts 60 seconds (`logitrack-web/features/auth/utils/navigationProfile.ts:10`, `logitrack-api/internal/authz/webroutes.go:23`, `logitrack-web/lib/queryClient.ts:144`, `logitrack-web/lib/bff/edgeGate.ts:82`). These boundaries must include support mode and disclosure changes.

## Decision

1. **Use an explicit support session, never membership or impersonation.** Extend `POST /v1/auth/tenant` with member/support/leave modes. Support requires a current human web session and database platform_admin grant; email addresses and the separate platform role `support` do not qualify. Allow active/pending/suspended own-fleet/carrier tenants, never quarantine. Persist mode/context version and issue `tid`, virtual `rol=support_readonly`, `sm=support`, `scv`, `sacv` with the real `sub/sid/plt` actor axis; clear driver/dispatcher/customer axes. Do not add memberships or update `users.last_tenant_id`. Refresh preserves/revalidates support; leave restores a usable real membership or platform-only context. No idle timeout or additional support-only absolute cap (D4); normal session expiry remains effective. See spec §4.2 and `logitrack-api/internal/auth/token/token.go:35`.

2. **Close human header impersonation and classify actual requests (D1, findings 1/3).** Remove `x-act-on-tenant` from the BFF forwarded-header allowlist and all web callers. Go refuses UUID and `*` tenant-data overrides for every human in member/support/platform-only modes, including platform_admin and platform role `support`, regardless of consent. `platform:cross_tenant_write` no longer overrides tenant writes. Bind immutable endpoint policy at registration after authentication and before business handlers/idempotency; group authentication cannot classify an endpoint using a middleware-prefix route. Test `/v1/me` group middleware, parameterized endpoints, explicit/automatic HEAD policies and both listeners; unknown registrations fail CI and deny at runtime. Policies include phase, capability plane, target resolver, projection adapter and strict query/decoded-body predicates, or split mixed routes. Matrix `layer/tenantId`, API-key body `tenantId`, tenant PATCH lifecycle/profile fields and IAM tenant targets must never reclassify tenant mutations as controls; unknown/conflicting/ambiguous discriminants deny. After explicit own-account/session and pure platform exception classification, **every tenant mutation returns `403 support_read_only` first**, including a mutation in a deferred domain; deferred/unknown reads return `403 support_view_unavailable`. Own-account `GET/PATCH /v1/me`, device PUT/DELETE, own-session GET/DELETE and `/v1/me/tenants` are allowed only for the authenticated caller, never tenant data; proposed future `/me*` routes gain no blanket exception. Both Shopee PDF generation and Cartrack probe GETs submit jobs and are writes. Maintain service guards before IAM/storage/jobs shortcuts. Support RLS is READ ONLY, exact selected tenant, `Bypass=false`, **`Steward=false`**, no contractor/dispatcher reach; Phase 1 has no stewardship exception. Spec §4.3 defines the mixed-route policy, exact method/route platform-control table, own-account exceptions and Phase 1 seed; P1.0 diffs `api/support-policies.json` against that seed before release.

3. **Separate platform controls and project tenant data by its target owner (D1/D5, finding 4).** Preserve independently authorized pure platform controls: platform-role/dispatcher grants, platform matrix/keys, tenant provisioning/lifecycle and mobile release/floor controls. Their dedicated context has no implicit selected tenant. Edge/Go route gates and sidebar/quick-jump resolve route class first, then use `capabilities ∪ platformCapabilities` only for platform-class routes (including mobile release and tenant administration); tenant writes never use that union. Phase 1 adds `users:view_sessions` **for the platform plane only**, independent of revoke rights; tenant Security remains deferred. The Phase 1 new tenant read keys are `fleet:view_maintenance` and `fleet:view_subcontractors`; audit all GETs behind shared management guards. Waitlist and system status are platform-plane reads: during support use reviewed counts/status DTOs without lead PII in either consent state, never selected-tenant consent as authority. Tenant membership/profile/password/driver-link work is refused while in support, even ON. Quarantine rehome and queue replay have tenant/external effects: require leaving support and dedicated maintenance authorization/audit, never a blanket cross-tenant-write capability. Migrate every consumer in spec §4.3's verified D1 map: users API/UsersPage/ActiveUsersPanel → `/v1/platform/users[/:id]`; tenants API/TenantAdminsDialog → `/v1/platform/tenants/:id/members` and platform users; security `reach/events/overview/apiKeys/sessions` APIs and SecurityAuditPage/SecurityOverviewPage/RoleMatrixPage/ApiKeysPage/ActiveUsersPanel → explicit `/v1/platform/security-events`, `/v1/platform/security/overview`, `/v1/platform/stats/users-by-role`, `/v1/platform/api-keys`, `/v1/platform/users/:id/sessions`; mobile-release installations/MobileClientsPage/MobileReleasePage → `/v1/platform/app-installations[/stats]`. Shared `lib/{goFetch,goPages,goQuery,queryKeys}.ts`, `lib/realtime/polling.ts` and BFF drop header propagation/comments in favor of typed endpoint plane/target. Dashboard's support user-count tile uses P1.3's selected-tenant projected summary count, not the Security hooks; ordinary platform hook callers use the replacement count endpoint. P1.0 CI forbids `x-act-on-tenant` (case-insensitive) and `ACT_ON_TENANT_HEADER` in non-test web code; Go retains only the rejection/audit boundary, no human override consumer. Each owner fixes its header/ActOnTenant tests in the same merge, including P1.0's deferred-package sweep. Apply the **target tenant's own consent** to every row/nested join of platform-authorized reads and control responses, in every mode including no `tid` and platform role `support`. A ON cannot reveal B OFF. Existing platform/global paths must adopt that projection or refuse; new safe endpoints cannot coexist with an unmasked alternate path. Include tenant/subcontractor detail, `idCardNumber`, documents, memberships, sessions, errors and exports. Within a tenant support view, global/foreign-owner PII stays masked even ON. Unknown ownership stays masked/counts-only. Ordinary access authorized by real membership retains its member contract.

4. **Persist consent and prevent platform IAM from manufacturing it (D2, finding 2).** Consent defaults OFF, has a monotonic version/actor/time and no expiry. Only a live eligible database tenant_admin in ordinary member mode for that tenant may change it via CAS; virtual roles/platform capabilities/header reach do not qualify. **Active tenant_admin = active membership with role tenant_admin regardless of user.disabled** (stored as `users.status` today). Gate every platform-originated action on a tenant_admin account/membership: grant/raise, disable, enable, delete, demote, remove membership, driver link/unlink, password reset, temporary password and invite. Retain the general grant/reset/invite restrictions too. Outside support each affected tenant must have no active tenant_admin (onboarding) or consent ON; tenant writes remain forbidden in support. Resolve all affected tenants from **pre-mutation** memberships and shared-account relationships; serialize the check with membership/status/consent changes. Disabling/demoting/removing the sole admin cannot create its own onboarding window.

   Record every platform membership grant's `granted_by_platform`, grantor/time and grant version; preserve history across role changes/removal. Stamp `credential_reset_by_platform_at` for platform-set credentials, retain origin through invite/reset redemption, force must-change-password and invalidate credentials/sessions through the existing path. No account whose latest credential is platform-set may toggle consent or ratify until its holder sets a self-chosen password; record completion server-side, recheck it transactionally and block again on any later platform reset. Platform administrative password changes cannot masquerade as holder completion. Ordinarily a distinct eligible tenant_admin whose membership predates the grant must ratify it; platform/self/unratified ratification cannot qualify. **Decided first-admin bootstrap:** the recorded first tenant_admin created by a platform admin during initial onboarding becomes eligible to toggle/ratify only after holder self-chosen completion through must-change-password. Retain platform provenance and an immutable first-grant record; no automatic ON, invented self-ratification or reusing the exception after removal.

   **Decided migration default:** pre-existing memberships without platform-actor evidence get `granted_by_platform=false`; only evidenced grants are flagged for review by the tenant's own eligible admin. Display them through member DTO fields `grantedByPlatform`, `ratifiedAt`, `grantVersion`, `eligibilityBasis`, viewer-relative `eligibleToRatify`, plus consent DTO `eligibleToToggle`. Settings → Support access includes Pending ratification and an EN/TH confirm dialog. Ratification POST uses grant-version CAS: 409 reloads, 403 rejects ineligible/self/platform actors; never optimistic eligibility. If no eligible reviewer exists, only an evidenced first onboarding grant may use the decided bootstrap; other flagged grants remain ineligible. This is a decision, not a rollout-wide ambiguous-provenance block or an open question.

   Every D2 action atomically emits tenant events and durable notifications to pre-operation existing active admins in every affected tenant; no secrets, and audit/outbox failure rolls back. Consent update, audit and realtime outbox are atomic. Add tenant/session/credential/provenance/first-grant/visit schema through migration 0027 (recheck number); P1.0 owns repository-wide `make sqlc` regeneration after source SQL handoffs, including models in otherwise unaffected packages. P1.2 depends on P1.1's Principal mode fields/credential hooks; deliver schema early to break that dependency cycle. Visit tables retain app-role INSERT/UPDATE grants with FORCE RLS/system-only WITH CHECK/USING, protected internal reads and no DELETE grant (`logitrack-api/internal/platform/db/system.go:37`). Test with `logitrack_app`, pooled-context reset, disabled-sole-admin reset/enable and demote/remove/delete/driver-link attacks, ON reset→ratify, shared-account/concurrency/stale-session cases, self-chosen completion/re-reset, first-admin bootstrap and migration review.

5. **Require proof of server projection before disclosure.** A transport-neutral projector registers complete typed response schemas, including embedded structs, omitted fields, arrays/maps, metadata and raw JSON. The final outer response-admission guard covers both listener pipelines and error handling. It validates a request-local projector receipt bound to route, audience/versions, schema and final body/status/headers; direct writers or later substitutions discard the body/Location and return a safe refusal before first byte. Streams require separately registered broker/SSE adapters with scoped permits and live chunk checks, not a raw-writer exemption. CI independently discovers mounted-handler response types/writer call sites, including generic/interface branches, embedded and omitted fields; unresolved dynamic types fail closed. Negative fixtures add fields, DTOs and direct writers without editing an inventory and must fail discovery and runtime admission. Classifications stay outside generated sqlc. Mask after server cache lookup, without mutating shared cached objects. OFF human-readable sensitive values become `"****"`; money/rates become nullable values with explicit redaction metadata; files/keys/tokens and sensitive objects become null placeholders. Keep approved dates/status/counts/plates. ON still strips secrets and enforces scope/classification. Define money fields once in generated `shared-docs/schemas/supportAccess.ts` (`MoneyValue = number | null`); domain web APIs import/re-export those DTOs before admission. The mandatory `goFetch`/`goPages.fetchAllPages`/query metadata adapter preserves field paths through infinite-page flattening, nested views and exports; a generic cast is not a parser. Type-aware lint rejects `|| 0`, `?? 0`, Number/unary coercions and unchecked aggregates/formatters on monetary fields. P1.0 lint also forbids direct `formatThb` imports in Phase 1 trees; only the shared checked formatter may invoke it. Every money output uses `MaskedValue` before formatting, including genuine-null versus redacted-null handling. Classify map keys independently: never replace sensitive keys with `****`; project to `{code,label}` arrays or a reviewed curated mapping without collisions. Include driver tenant/customer labels and distance coordinates in coverage (spec §4.6). Ordinary numeric response contracts and billing calculations remain unchanged. Spec §4.6 is the target inventory; only admitted domains are served in each phase.

6. **Cover every admitted domain's transports and inference paths (D3/D5).** Phase 1 includes Dashboard and all Fleet & partners exports/files/SSE/jobs/dependencies, including maintenance money and partner documents. Spec §4.3 seeds Dashboard summary/locations/count-only badges (including sidebar use), trucks/detail/renewals, assignments, drivers/detail/documents, maintenance, partners, brokers/SSE/jobs, own-account `/me` routes, support-options and support-access GET, plus explicit platform controls. Drivers use a narrow code-only customer adapter; support disables full customer detail/name search and edit/import resolution. Truck-assignment pickers use only admitted trucks/drivers; shared accounting helpers do not admit accounting endpoints. P1.6 consumes the projected Dashboard count/badges and omits the incident widget and other unadmitted widgets without starting their requests; P1.7 consumes the same safe badge DTO in the sidebar. OFF refuses opaque exports/downloads; ON reads only existing authorized artifacts through an authenticated broker with live consent/session/source-domain/owning-tenant checks, never public signed URLs. No generation or tenant job submission. Broker object tenancy must equal the selected tenant. Use only reviewed DB-row Content-Type (never request input), `X-Content-Type-Options: nosniff`, `Content-Security-Policy: sandbox; default-src 'none'`, `Content-Disposition: attachment` for PDFs and `Cache-Control: private, no-store`, preserved through BFF GET/HEAD/Range. Prefer image decoding/re-encoding for inline previews, refuse decode failures or serve attachment-only; declared MIME is not byte validation. Support images bypass shared optimizer caches. Context-bound human upload brokering and draining old bearer PUT grants precede entry. SSE live/replay sends scoped identifier invalidations only for admitted domain families. Job results/errors need type projections; unknown/foreign/deferred sources refuse. Reject sensitive OFF search/filter/sort/cursor predicates. **Public evidence keeps its existing sharing contract as an accepted residual risk**; support sessions never receive/mint evidence URLs/tokens. Later authenticated galleries return only authorized broker paths when their source domain is admitted. Visible liters × public fuel price, payroll quantities/categories × independently known rates, and distances/trip counts × known tariffs can still reveal estimates; D5 accepts these inference risks (spec §8). This is masking, not anonymization.

7. **Check live versions and preserve credential compatibility.** Every request using session-backed Go credentials checks the authoritative session mode/context version, including old member tokens after entry. Missing `scv` means zero only for an unchanged legacy member session; refresh issues explicit versions. Preserve sessionless Firebase shim authentication/contracts without querying a nonexistent session; shims/machines/mobile cannot carry support mode. No per-session advisory lock is required: a legitimate member write admitted before transition may finish; later requests fail stale `scv`, with transaction-time rereads where needed. For disclosure, read current selected and explicit target tenants' consent from PostgreSQL, then revalidate before serialization/first byte. `SELECT ... FOR SHARE` in a separate policy transaction (domain reads remain READ ONLY), on tenant rows in stable ID order, serializes final authorization with consent UPDATE, not network delivery. Bound pages to 100 rows and at most 100 distinct owners including joins, splitting larger reads; no per-target advisory-lock fan-out; check bounded stream chunks. DB failure fails closed. Stale claims use `token_expired` / `claims_changed`; notifications clear displays but never authorize reads. Refuse support at Firebase custom-token/bridge service entry points before legacy admin mapping, UID/mirror work or signing, including forged mobile/shim support principals and web/both bridge configurations. Require web bridge disabled (off or mobile-only) before support entry and test zero signer calls. Verify pre-migration web/android/ios tokens without scv before any transition, refreshed versions, sessionless callable shims, mobile SSE and ordinary numeric DTOs. Already delivered data cannot be recalled.

Close visits idempotently on leave, switch, logout, revocation/platform-role loss or session expiry; tab closure/inactivity is not an exit (D4). Cleanup records effective termination time even after restart. Entry/consent and D2 IAM operations fail if their required event/outbox append fails. Tenant admins see events/notifications in normal member mode from Phase 1 even while the tenant Security support domain is deferred; support copies obey projection and phase gates. Use existing security catalog/feed and bounded entry/search/consent rate limits (spec §4.9).

9. **Extend the header and shell with phase-aware rendering.** Use the existing header switcher with a searchable modal: platform_admin sees eligible paginated tenants, ordinary users see memberships. Individual/unknown carrier names are person names under D5: mask OFF everywhere, use a reviewed non-person code or `TEN-<full lowercase canonical tenant UUID>` for identification and safe search. Existing code syntax can hold a romanized person name; unreviewed/person-derived codes are null OFF and never searchable, not presumed safe by regex. The support-options DTO returns its opaque tenant `id` for selection, but no other personal/external identifiers or contact data. Keep platform-first full staff navigation for carrier support. Dashboard/Fleet pages load projected DTOs; all other tenant destinations show localized EN/TH “Not yet available in support view” without running loaders, effects or legacy fallbacks. Carrier billing remains truthful read-only unavailable/empty, never another tenant's billing. Add banner/Leave and member-mode consent Settings; apply provenance, first-admin and credential eligibility to the toggle; include the Pending ratification read model/confirm dialog from decision 4. Write affordances use mutation capabilities. Go/web route matching decodes canonical segments once, prefers literal then full parameter-template matches over list-prefix fallbacks, rejects ambiguous/invalid paths and tests real UUID and encoded edit/new URLs. Preserve ordinary decisions when splitting read keys: derive each new key from the effective old permission after all override/class restrictions; do not add unconditional defaults or independently editable new overrides in this release. Test platform deny/tenant grant and platform grant/tenant deny and bump the resolver fingerprint. ## Consequences

- A support visit grants no membership or tenant write authority. Consent controls disclosure; platform IAM cannot manufacture an eligible consenting membership through a grant or takeover. Platform-originated actions remain visible to the tenant and notify existing admins. The first onboarding admin gains eligibility only after holder self-chosen completion; existing no-evidence memberships use the false migration default. These are settled owner decisions; only Phase 2+ slice delivery order remains open.
- Closing `X-Act-On-Tenant` affects shipped platform pages and direct human API clients. Their purpose-built replacements, target-tenant projection and IAM restrictions are Phase 1 prerequisites in **all** modes, including the separate platform role `support`; that role does not gain support entry. Existing pure controls remain explicitly authorized; tenant-effect maintenance requires leaving support.
- Full staff navigation is available immediately, while data coverage grows by domain. Phase 1 includes Dashboard and trucks, truck assignment, drivers, renewals, maintenance and partners, with exports/files/SSE. Deferred pages return a truthful localized unavailable state in both consent states. Complete domain masking is not required to ship unrelated later domains, but no unreviewed endpoint may disclose data.
- RLS supplies exact row reach with no stewardship/contractor inheritance; projection supplies the field boundary. Target-tenant policy applies to platform reads even with no active tenant. Global/foreign-owner personal data stays masked in tenant support views. Carrier billing ownership is unchanged, and individual-carrier labels use masked person fields plus code/opaque references OFF.
- Nullable support values and metadata require shared client-contract/rendering changes; ordinary member/mobile/shim contracts and monetary calculations remain intact. Read-key splits derive from effective old rights and preserve live overrides as well as the UI3F fixture. Registration predicates and outer projection admission add integration work beyond page edits.
- Live policy checks add indexed PostgreSQL reads; file brokering adds bandwidth and bounded streaming checks. No support idle timeout is added: a forgotten tab can retain context until actual session/context termination. Persistent consent and long visits are explicit owner choices, with entry/leave events and revocation checks.
- **Accepted pending-partner KYC limitation:** consent OFF keeps ID cards/documents masked even when no eligible admin exists. Platform reviews documents out of band; no in-product exception. This is a residual operational risk, not an open owner question.
- Existing independently held public evidence links remain usable under their sharing contract, outside the authenticated support channel. Approved dates (including birth date), stable IDs/plates/status/counts and external knowledge can identify records or estimate masked amounts. D5 accepts the evidence/inference residual risks; neither OFF nor masking claims anonymity or recall of delivered data.
- Rollback disables entry, closes visits/invalidates contexts and clears caches; later-domain rollback removes only its allowlist entries. Preserve consent, provenance/ratification and audit history. **Retain D1 header closure, D2 IAM restrictions and target-tenant projection**; never fall back to the previous unrestricted inspector/reset path or route support to old replicas.
- Implementation later reconciles Appendix C's session/header semantics, Appendix A's schema, Appendix B's endpoints/events and generated contracts. This ADR remains Draft - awaiting owner approval and does not declare ADR 0029 Accepted or start implementation. Only the two requested documents are authored in this task.

## Alternatives considered

- **Insert temporary tenant_admin memberships or reuse `X-Act-On-Tenant` as-is.** Rejected: both create the wrong authority; header impersonation explicitly enables writes and contractor reach. A temporary membership also changes real IAM state and the remembered login tenant (`logitrack-api/internal/iam/authorize.go:35`, `logitrack-api/internal/auth/me.go:392`).
- **Reuse the platform role `support`.** Rejected: it is an existing narrower platform role, not the required platform_admin tenant session; broadening it would grant access to a different population (`logitrack-api/internal/authz/roles.go:70`).
- **Grant every tenant_admin capability and hide action buttons.** Rejected: management keys and `HasPlatform` shortcuts would still admit crafted requests, jobs and automatic effects. Some GET requests themselves enqueue writes (`logitrack-api/internal/fleet/locations/locations.go:214`).
- **Client-only or BFF-only masking.** Rejected: raw data would already have left Go; API callers, file redirects, event bodies and job results remain exposed. The BFF is a transport/auth-cookie boundary, not the authoritative domain projection (`logitrack-web/lib/bff/goProxy.ts:13`).
- **Mask serialized JSON by matching field-name substrings.** Rejected: names such as `value`, `meta`, `details`, `name` and `displayCostThb` have different meanings, and raw JSON embeds sensitive values. Typed classification plus domain projections can be checked exhaustively (`logitrack-api/internal/hr/payroll.go:48`, `logitrack-api/internal/maintenance/records.go:28`).
- **Put consent only in JWT claims or a TTL cache.** Rejected: OFF would wait for token/cache expiry and dropped notifications could preserve clear access. Existing edge/cache refresh behavior illustrates the stale-data window (`logitrack-web/lib/bff/edgeGate.ts:135`, `logitrack-web/lib/queryClient.ts:183`).
- **Keep issuing short-lived storage/evidence bearer links to support.** Rejected for the new support channel: copied links bypass current session/consent checks; default storage presigns last an hour and evidence tokens default to no expiry (`logitrack-api/internal/storage/service.go:36`, `logitrack-api/internal/storage/evidence.go:19`). D5 explicitly preserves independently held public links as a residual risk; they are never issued to support.
- **Automatically expire consent, add a support idle timeout or require renewed approval on every visit.** Rejected: consent persists until a tenant_admin turns it OFF, and D4 explicitly chooses no idle timeout/additional support cap. Normal session expiry still ends a visit.
- **Enable all domains together, or expose raw data until masking arrives.** Rejected by D3: ship the complete Phase 1 boundary, keep other domains unavailable, and admit each later domain only after its tests pass.
